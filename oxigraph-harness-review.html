The missing integration is now connected

Earlier command wrapper

The previous repair supervised native build/test commands. The conversation still connected worker handoffs, edit application, repair and review. Calling that a complete build workflow was too strong.

Task workflow controller

The controller now chooses those transitions and validates their source-bound responses. Native Codex agents remain the workers; root remains the sole writer. MetaHarness kernel stages run native worker callbacks, and the existing command runner handles deterministic checks.

What we learned from the other projects

Reuse working MetaHarness components and native coding hosts. Keep the necessary project integration outside the kernel where appropriate. Do not invent another platform, restart evolution or assume upstream retries provide repair feedback and prerequisite gating.

Who does the building?

  1. Controller → live MCPThe host retrieves the actual task/control. The controller verifies task identity, exact scope and the owner hold before proceeding.
  2. Kernel → native workerA native implementation agent receives scoped source and a completion check. It proposes file contents; it cannot write or run tests.
  3. Controller → root applyRoot applies the exact proposal with apply_patch. The controller checks expected file bytes and that preexisting work outside scope is unchanged.
  4. Runner → native checksNo model call. Failed checks stop later checks/review and return bounded failure evidence to repair; the revised source is tested again.
  5. Kernel → independent reviewA distinct native worker reviews the exact candidate and actual results. Rejection feeds findings into repair, then fresh checks and review.
  6. Host → MCP readbackThe host stores accepted evidence and retrieves it. The controller verifies the exact value, then stops at ready-for-owner-review.

Concrete findings corrected during this repair

Fixed

Missing orchestration

The ordinary controller now connects task lookup, worker result, root application, check, repair, independent review and exact readback. The host still executes tools; no replacement agent platform was introduced.

Fixed

Unproductive repair detection

The repeated-failure identity excludes volatile timing fields. Changing duration alone cannot make an unchanged failed repair appear to progress.

Fixed

Unbounded feedback

Spec, source, result and request sizes are structurally bounded. Full process output stays local; repair receives exact evidence identity and inspectable log paths.

Fixed

Host stream errors

Input, output and readline interface errors reject the pending action and clean up its listeners. Real failing regressions became passing tests through native proposals and root application.

Fixed

Evidence representation bugs

Canonical object hashing prevents JSON key order from rejecting identical file bytes. Node feedback now uses the Node test summary instead of the unrelated Cargo zero counter. Both have regressions.

Finite completion, explicit limits

What is deliberately retained

  • Native coding host executes MCP and agent tools; root applies edits and commits.
  • Only per-worker stages use HarnessKernel; the outer controller supplies dependency gating and repair feedback.
  • Source-bound host responses are inspected, not independently authenticated.
  • Boundary checks are not a filesystem sandbox or proof against transient concurrent edits.

What is not claimed

  • No durable crash-resume, unattended dispatcher or autonomous publication.
  • No new platform, router training, evolution cycle or changed frozen G1 evidence.
  • No application build/test under the current hold and no new product behavior credited.
  • No semantic qualification, G1.7 activation, release or lifting of the owner hold.

The host must remain attached to answer typed requests. The local event log supports inspection, not automatic recovery. Native subscription/model unavailability stops with the exact client, model and error; there is no provider-key fallback or hidden model substitution.

+import { createInterface } from "node:readline";
+import { writeFileSync } from "node:fs";

+export function stdioHost(directory, input = process.stdin, output = process.stdout) {
+ const lines = createInterface({ input, crlfDelay: Infinity });
+ let pending;
+ let closed = false;
+ const detach = () => {
+ input.removeListener("error", onInputError);
+ output.removeListener("error", onOutputError);
+ lines.removeListener("error", onLinesError);
+ lines.removeListener("line", onLine);
+ lines.removeListener("close", onClose);

+ if (closed) return;
+ closed = true;
+ if (pending) { clearTimeout(pending.timer); pending.reject(error); pending = undefined; }
+ detach();
+ lines.close();
+ };
+ const onInputError = (error) => fail(error);
+ const onOutputError = (error) => fail(error);
+ const onLinesError = (error) => fail(error);
+ const onLine = (line) => {
+ if (!pending) return fail(new Error("Unsolicited host response"));
+ try {
+ if (Buffer.byteLength(line) > 2 * 1024 * 1024) throw new Error("Host response exceeds structural limit");
+ const result = JSON.parse(line);
+ clearTimeout(pending.timer);
+ const { resolve } = pending;
+ pending = undefined;
+ resolve(result);
+ } catch (error) { fail(error); }
+ };
+ const onClose = () => fail(new Error("Host input closed before workflow completion"));
+ input.on("error", onInputError);
+ output.on("error", onOutputError);
+ lines.on("error", onLinesError);
+ lines.on("line", onLine);
+ lines.on("close", onClose);
+ return {
+ request: (request) => new Promise((resolve, reject) => {
+ if (closed || pending) return reject(new Error("Host bridge closed or already awaiting a result"));
