What this fixes

Before

The engineering harness existed, but its active registry covered historical G1 candidates. Current product changes used native agents and direct Cargo commands.

Ruflo task rows, installed packages and passing tests did not establish that the current build ran through a harness.

After

A separate ordinary-delivery entry point now runs native commands through the existing Agentic-QE process runner. Each run binds its command, completion check, source inputs, tool versions, output and actual result.

The frozen candidate runtime and semantic qualifier are unchanged. This is an additive execution lane, not another qualification programme.

Review focus

Is the explicit native-coordinator workflow sufficient for everyday delivery? The CLI supervises commands; it deliberately does not authenticate MCP task IDs or automatically dispatch models. That distinction is part of the contract, not an omitted claim.

The path every programme build uses

  1. Recover & selectNative coordinator retrieves the live Ruflo task/control over MCP, honors the review hold and defines one observable completion check.
  2. Execute & observeExplicit worker model/effort when needed. All build/test commands use the delivery entry point and its native process runner.
  3. Review & hand offInspect real results, update the live task and repository memory, then read back the exact evidence. A command pass is not task completion.

Independent findings and corrections

Corrected

Unverified task attribution

The run requires a completion check and binds the deterministic plan/hash. Its task ID remains explicitly coordinator-supplied and unverified locally; status is command-passed. The native coordinator performs the real MCP lookup and outcome readback.

Corrected

A stale or unrelated artifact

Artifact selection is restricted to a compatible Cargo build, binary and profile. It requires one matching compiler-artifact event from that command and retains Cargo's fresh flag. An old file's mere presence is insufficient.

Corrected

Unrestricted high-effort overrides

Max/Ultra now require --selection owner or --selection unresolved, as well as the explicit model, effort, reason and completion check. Parallel work alone does not justify either.

Corrected

Nonregular untracked inputs

Source capture now rejects an unsupported nonregular untracked entry with an explicit diagnostic, rather than treating it as a regular readable source file.

What this does not prove

Deliberate boundaries

  • No automatic model transport or MCP synchronization inside the CLI.
  • No operating-system interception of commands run outside the harness.
  • Before/after source checks do not prove absence of transient concurrent edits.
  • No change to frozen G1 registries, expected results or protected runtime.

Still not claimed

  • No semantic qualification, G1.7 activation, promotion or application release.
  • No full CLI artifact rebuild during the owner hold; artifact-event binding has positive/negative contract tests.
  • No product milestone credited for harness/documentation work.
  • No lifting of the main-build pause by this page or the timer.

Ruflo caveat: the task status read back as completed/100, but its completedAt and result fields stayed null. The source-bound command evidence was therefore stored and verified separately. Hook-generated quality/duration values were not used as measured performance or model-quality evidence.

+#!/usr/bin/env node
+import { routeDelivery, runDelivery } from "../src/delivery.mjs";
+
+const help = `Ordinary Oxigraph delivery (ADR-0043)
+ run --task ID --check "observable completion" [--timeout-ms N] [--artifact target/release/oxigraph] -- cargo test --locked -p oxigraph --test store
+ run --task ID --check "harness contracts pass" -- node --test --test-reporter=tap tools/engineering-harness/test/delivery.test.mjs
+ route --task ID --role implement --check "observable completion" [--model MODEL --effort EFFORT --reason REASON --selection owner|unresolved]
+Use live Ruflo MCP before dispatch and after execution. Route is a plan, not a model invocation.
+No shell, publication, provider execution, qualification, or G1.7 commands are admitted.
+`;
+try {
+ const [action, ...args] = process.argv.slice(2);
+ if (!action || action === "--help" || action === "help") {
+ process.stdout.write(help);
+ } else {
+ const split = args.indexOf("--");
+ const options = split < 0 ? args : args.slice(0, split);
+ const values = {};
+ const allowed = action === "run" ? ["--task", "--check", "--timeout-ms", "--artifact"] :
+ action === "route" ? ["--task", "--role", "--check", "--model", "--effort", "--reason", "--selection"] : [];
+ for (let i = 0; i < options.length; i += 2) {
+ if (!allowed.includes(options[i]) || Object.hasOwn(values, options[i]) || !options[i + 1]) {
+ throw new Error("Unknown, duplicate or incomplete delivery option");
+ }
+ values[options[i]] = options[i + 1];
+ }
+ if (action === "run" && split >= 0) {
+ const run = await runDelivery({
+ taskId: values["--task"], completionCheck: values["--check"], argv: args.slice(split + 1),
+ timeoutMs: values["--timeout-ms"] === undefined ? undefined : Number(values["--timeout-ms"]),
+ artifact: values["--artifact"],
+ });
+ process.stdout.write(JSON.stringify({ status: run.status, directory: run.directory, taskId: run.taskId,
+ sourceStable: run.sourceStable, artifact: run.artifact, failure: run.failure }) + "\n");
+ process.exitCode = run.status === "command-passed" ? 0 : 1;
+ } else if (action === "route" && split < 0) {
+ process.stdout.write(JSON.stringify(routeDelivery({ taskId: values["--task"], role: values["--role"],
+ completionCheck: values["--check"], model: values["--model"], effort: values["--effort"],
+ reason: values["--reason"], selection: values["--selection"] }), null, 2) + "\n");
+ } else { throw new Error("Expected run with literal argv or route with role and completion check"); }
+ }
+} catch (error) {
+ process.stderr.write(`${error.message}\n`);
+ process.exitCode = 2;
